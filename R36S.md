# R36S / ArkOS builds

The R36S (RK3326, Cortex-A35, 640×480) runs ArkOS, whose userland is
Ubuntu 19.10 (eoan): glibc 2.30, GCC 9's libstdc++ (`GLIBCXX_3.4.28`),
SDL2 2.0.10. A binary linked against nixpkgs' glibc does not start there.

## Toolchain

**ARK-1.** Build against a sysroot of eoan arm64 `.deb`s fetched from
`old-releases.ubuntu.com` with their archive hashes (STACK-8), extracted with
`dpkg-deb -x`; absolute symlinks inside are rewritten into the sysroot.
Reference: xanatoo / kurvenrausch `nix/r36s.nix` (`arkos-sysroot`, FLAKE-1).

**ARK-2.** The compiler is nixpkgs' `pkgsCross.aarch64-multiplatform` GCC,
but every header and library comes from the sysroot: `-nostdinc -nostdinc++`,
`-isystem` for `usr/include/c++/9` (+ multiarch, `backward`), GCC's own
`include` only for compiler intrinsics, `-nostdlib++ -lstdc++` against the
sysroot's `libstdc++.so.6`, `--dynamic-linker=/lib/ld-linux-aarch64.so.1`,
`-mno-outline-atomics` (no `__aarch64_*` helpers in GCC 9's libgcc).
No ABI shims are needed then.

**ARK-3.** SDL2 is linked against a stub `libSDL2-2.0.so.0` (sysroot symbols,
empty bodies) so the device's own SDL2 (KMS/DRM, ArkOS build) is used at run
time. Use only SDL ≤ 2.0.10 API (e.g. no `SDL_RenderGeometry`; ImGui's SDL
renderer backend needs a patch).

**ARK-4.** Check every R36S build: the highest `GLIBC_` / `GLIBCXX_` /
`CXXABI_` version in `objdump -T` must not exceed what the sysroot's
`libc.so.6` / `libstdc++.so.6` define, and the binary must start under
`qemu-aarch64 -L <sysroot>` (`--version`, `--show-paths`, with the SDL2 stub
on `LD_LIBRARY_PATH`: the real SDL2 pulls ALSA etc., which the sysroot does
not carry).

**ARK-5.** Libraries the device may lack (anything beyond SDL2, FreeType,
Fontconfig, zlib, libpng, OpenSSL 1.1) are added to the sysroot as eoan debs
and shipped in the port's `libs/`; the launcher prepends
`$GAMEDIR/libs` to `LD_LIBRARY_PATH`.

## C++ standard

Results from xanatoo (2026-10-29, GCC 16.2 cross, libstdc++ 9.2 headers):

| | Status |
|---|---|
| `-std=c++20` compiles and links | **works** (xanatoo, thumtoo off) |
| C++20 language features: defaulted `operator==`, designated initializers, `std::string_view`, `std::filesystem` (in `libstdc++.so` since GCC 9.1, no `-lstdc++fs`) | **works**, binary needs ≤ `GLIBCXX_3.4.26`, starts under qemu with eoan libs |
| `CMAKE_CXX_STANDARD=17` on C++20 code | fails (defaulted `operator==` is C++20) |
| C++20 library headers GCC 9 does not ship: `<span>`, `<ranges>`, `<compare>` (so `operator<=>`), `<concepts>`, `<numbers>`, `std::bit_cast` (`<bit>` itself exists), `<source_location>`, `<format>`, `std::jthread` / `<stop_token>`, `<semaphore>` / `<latch>` / `<barrier>`, coroutines | **not available**: language features that need these headers do not work either. Not tried; from libstdc++ 9's header set. |
| Running on the device | **works** (xanatoo C++20 build on the R36S, 2026-10-29) |

**ARK-6.** A game that targets the R36S may use C++20, but only the
language features and the library parts that libstdc++ 9 has. The R36S
build passes `-DCMAKE_CXX_STANDARD=20`; it fails to compile when code uses a
newer header, which is the intended guard.

## Libraries

| Library | Status |
|---|---|
| SDL2 2.0.10, FreeType 2.9, Fontconfig 2.13, zlib, libpng 1.6, brotli, expat, OpenSSL 1.1.1 | **works** (eoan debs) |
| SQLite 3.29 (`libsqlite3-0`, `libsqlite3-dev`) | **works**; ship `libsqlite3.so.0` in `libs/` (ARK-5). CMake's `FindSQLite3` needs `-DSQLite3_INCLUDE_DIR` / `-DSQLite3_LIBRARY` into the sysroot |
| libvips (thumtoo) | **not available**: not in the sysroot; eoan's libvips42 8.8 plus its dependency tree was not tried. Build with thumtoo off (stb_image decoding) |
| Nothing in nixpkgs linked into the R36S binary | required: nixpkgs libraries need a newer glibc |
